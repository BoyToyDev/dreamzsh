# История изменений

В этом файле фиксируются все значимые изменения DreamZSH.

Это русская версия истории изменений. Синхронизированная английская версия
находится в `CHANGELOG.md`. Новые изменения сначала добавляются в раздел
`Unreleased`, а при выпуске релиза переносятся в раздел с номером версии.

## Unreleased

### 2026-07-24

#### Добавлено

- Добавлены сегментные темы Catppuccin, Tokyo Night, Dracula и Gruvbox с
  состоянием Git, результатом команды и временем.
- Добавлена поддержка macOS: нативные контрольные суммы через `shasum` и
  отдельная задача CI.

#### Изменено

- Пересекающиеся темы `dream`, `work` и `pro` заменены совместимой миграцией на
  `dream-smart` и `dream-mini`.

### 2026-07-23

#### Добавлено

- Добавлены записи каталога со ссылкой на оригинальные Git-репозитории через
  метаданные `source_url`, `source_ref` и `source_entrypoint`.
- Добавлены атомарная установка и обновление с отслеживанием коммитов как
  каталога, так и upstream-проекта.
- Registry-тесты теперь покрывают просмотр, информацию, установку, загрузку и
  обновление плагинов из upstream-репозиториев.
- Перед установкой из каталога теперь проверяются зависимости: отсутствующие
  плагины и системные команды показываются до загрузки кода и изменения конфига.

### 2026-07-22

#### Добавлено

- Добавлены синхронизированные английская и русская версии README с
  переключением языка и записанной демонстрацией терминала.
- В `dreamzsh uninstall` добавлены автоматизация через `--yes` и поддержка
  `ZDOTDIR`.
- В Linux CI добавлены отдельные тесты обновления и удаления.

#### Изменено

- `plugin install` теперь сразу включает установленный плагин; из CLI удалена
  лишняя опция `--enable`.
- Официальный каталог теперь автоматически загружается командами `browse`,
  `info` и `install`; `plugin repo add` используется только для дополнительных
  репозиториев.
- `dreamzsh update` теперь использует настроенную upstream-ветку вместо
  жёсткой привязки к `origin/master`, отказывается работать при изменённых
  отслеживаемых файлах или разошедшейся истории и хранит маркер проверки вне Git.
- `dreamzsh reload` теперь загружает `.zshrc` в текущей оболочке и сохраняет её
  состояние; `--exec` оставлен для полной замены процесса.
- Предпросмотр темы теперь применяется к текущей интерактивной оболочке, не
  меняя сохранённую тему.
- Статистика запуска теперь показывает измеренное время загрузки в миллисекундах.
- При удалении `.zshrc` обновляется атомарно, а управляемый блок интеграции
  проверяется до внесения изменений.

### 2026-07-21

#### Добавлено

- Добавлен встроенный официальный репозиторий плагинов `official` на основе
  `BoyToyDev/dreamzsh-plugins`.
- Добавлено управление репозиториями через `plugin repo list`, `add`, `remove`
  и `update`.
- Добавлены `plugin browse`, удалённый `plugin info` и установка плагина по
  имени из registry с необязательным выбором через `--repo`.
- Добавлены безопасное чтение метаданных без их выполнения, атомарное
  кэширование registry, атомарная установка и обновление с учётом источника.
- Добавлены автономные тесты registry на изолированных локальных Git-репозиториях.
- Добавлена shell-функция `dreamzsh`, благодаря которой `dreamzsh reload`
  заменяет текущий интерактивный процесс Zsh, а не только печатает инструкцию.
- Для lifecycle hooks добавлены удаление регистрации, защита от повторной
  регистрации, диагностика ошибок и передача имени плагина в `PRE_PLUGIN` и
  `POST_PLUGIN`.
- Hooks `PRE_PROMPT` и `POST_PROMPT` подключены до и после обработки prompt
  активной темой.
- Метаданные зависимостей разделены на `requires_plugins` и
  `requires_commands`; старое поле `requires` сохранено как совместимый alias
  зависимости от плагина.
- В CI добавлены тесты lifecycle hooks, reload и зависимостей плагинов.

#### Изменено

- README обновлён с учётом текущего установщика, CLI, официального репозитория
  плагинов, переносимых профилей, обслуживания и тестов.
- `plugin info` и шаблон нового плагина теперь показывают два явных типа
  зависимостей.
- Прямой вызов CLI для reload теперь объясняет ограничение дочернего процесса
  и предлагает `exec zsh` как запасной вариант.

#### Исправлено

- Исправлен оставшийся в `plugin enable` вызов удалённой старой проверки
  зависимостей.
- Исправлена регистрация первого callback в пустом lifecycle hook.
- Устранены повторная регистрация одного callback и молчаливое подавление
  ошибок hooks.
- Системные команды больше не интерпретируются как имена плагинов DreamZSH.

### 2026-07-10

#### Добавлено

- Добавлены отдельные каталоги `custom/plugins`, `custom/themes` и
  `custom/profiles` для пользовательских ресурсов.
- Добавлена установка сторонних плагинов через сокращение `owner/repo` или
  HTTPS Git URL с автоматическим поиском entrypoint и опциями `--name`,
  `--ref` и `--entry`.
- Добавлены атомарное обновление и подтверждаемое удаление сторонних плагинов
  через `plugin update` и `plugin remove`.
- Добавлен самодостаточный формат профиля версии 1 с SHA-256 checksums,
  snapshots сторонних плагинов, метаданными источников и дополнительными
  темами.
- Для `profile export` добавлены опции `--output`, `--from` и повторяемая
  `--include-theme`.
- Добавлен проверяемый импорт профиля с обнаружением конфликтов, `--overwrite`,
  `--yes` и необязательным `--apply`.
- В интерактивный установщик добавлена проверка наличия исполняемого файла
  `zsh`.
- Добавлена возможность установить Zsh через поддерживаемые пакетные менеджеры
  Linux.
- Добавлено определение login shell и интерактивное предложение переключить его
  через `chsh`.
- Добавлена справка для конкретных подкоманд плагинов, тем, профилей и резервных
  копий, включая варианты `dreamzsh plugin enable --help` и
  `dreamzsh help plugin enable`.
- Добавлен компактный набор smoke-тестов CLI с изолированным временным `HOME`.
- Добавлены smoke-тесты установщика для повторной установки, отсутствующего Zsh,
  интерактивной установки Zsh и переключения login shell.
- Добавлен GitHub Actions workflow только для Ubuntu: POSIX-проверки,
  синтаксическая проверка Zsh, ShellCheck и smoke-тесты.

#### Изменено

- `profile export <имя>` теперь экспортирует текущее управляемое состояние под
  произвольным новым именем и не требует существующего файла профиля.
- Созданные пользователем плагины и темы теперь сохраняются в `custom/`, не
  изменяя Git worktree DreamZSH.
- Поиск плагинов, тем и профилей теперь объединяет встроенные и пользовательские
  ресурсы, не перезаписывая встроенные.
- В выбранные компоненты backup теперь включаются пользовательские плагины,
  темы и профили.
- Сохранение конфигурации переведено на временный файл с атомарной заменой
  предыдущего конфига только после успешной записи.
- При атомарном сохранении сохраняется symlink конфигурации: заменяется его
  целевой файл, а не сам symlink.
- Финальное сообщение установщика теперь различает системы, где Zsh является и
  не является активным login shell.
- Для тем, регистрирующих runtime-ресурсы, введён lifecycle-контракт
  `dz::theme::cleanup()`.

#### Исправлено

- Исправлена ситуация, когда установка выглядела успешной при отсутствующем Zsh.
- Исправлено отсутствие предупреждения, если login shell не был переключён на
  Zsh.
- Исправлено сохранение старых `precmd` hooks и вспомогательных функций после
  переключения с `dream-mini`, `dream-context`, `dream-smart` или
  `dream-powerline`.
- Устранён риск обнуления `dreamzsh.conf` при ошибке записи конфигурации.
